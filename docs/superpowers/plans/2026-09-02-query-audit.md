# 查询审计与历史回看（P6）

> 状态：本地演示版已完成；真实数仓端到端验证待 Docker 环境可用。

## 目标

让每一次问数可追溯：谁在什么会话中提出了什么问题，系统如何理解、执行了哪条最终 SQL、返回多少行、耗时多久以及是否失败。

## 已完成

- 新增进程内 `QueryAuditService`，最多保留 500 条记录；
- 查询服务消费 SSE 事件时补齐原始问题、改写问题、最终 SQL、结果行数、终态和错误信息；
- 不保存完整结果集，避免审计记录重复存储业务数据；
- `GET /api/audits/me` 仅返回当前用户自己的最近记录，接口受 P5 Bearer Token 保护；
- 前端新增“查询审计”抽屉，可查看状态、耗时、改写问题、行数、失败原因和最终 SQL；
- 增加离线单元测试，覆盖成功、失败、未完成请求和跨用户隔离。

## 当前边界

- 记录存于 FastAPI 进程内，服务重启即丢失，不适合作为生产审计；
- 仅实现“本人记录”，管理员查看全局记录、筛选检索、导出与告警不在本阶段；
- 后续可用 MySQL 新增 `query_audit_log` 表替换服务实现，而不需要改动 LangGraph 或前端接口。

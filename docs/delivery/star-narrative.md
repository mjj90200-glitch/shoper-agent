## 30 秒电梯稿

「我独立开发了一个面向电商数仓的智能问数平台：业务人员用中文提问，系统经 LangGraph
多阶段工作流完成语义召回和 SQL 生成，四层安全防线保证只读执行，返回表格、图表和语音结论。
工程上做到 136 个后端测试 + 20 个前端测试全绿、一条 Compose 命令容器化部署、
健康检查/链路追踪/限流/审计完整，并维护 80 场景的回归评测集。」

## STAR 展开

**S（背景）**：电商业务人员看数需要写 SQL 或等数据排期；直接接大模型生成 SQL 又面临
注入、越权、拖库等安全风险，且回答过程不可解释、不可审计。

**T（任务）**：构建一个安全、可审计、可追溯的自然语言问数与经营分析平台，并按软件工程
标准完成可复现、可测试、可部署、可观测的工程化。

**A（做法）**：
1. **Agent 工作流**：LangGraph 编排 18 个节点——上下文改写、意图分流、字段/指标/取值
   三路并行召回（Qdrant 向量 + Elasticsearch 全文）、SQL 生成、校验纠错闭环、结果分析；
   多轮会话用 SQLite Checkpointer 持久化。
2. **SQL 安全**：sqlglot 语法树校验（仅单条 SELECT、白名单库表、拒文件/系统库/变量）→
   关键词扫描纵深 → 数据权限 AST 注入（区域经理自动限定授权地区、敏感列按字段标识拦截）
   → 数据库只读账号兜底，应用层全失效也写不了库。
3. **工程化**：配置启动即校验（缺失必填项快速失败且不泄密）、统一错误信封 + X-Request-ID
   全链路追踪、SQLite 版本化迁移、健康检查聚合五依赖、四类接口限流 + TTS 每日外发配额、
   136+20 测试全绿、前后端镜像一条命令部署。
4. **质量度量**：80 场景 85 轮回归评测集（含模糊表达、多轮指代、空结果、越权、Prompt 注入），
   管理端质量摘要输出成功率、成功查询 P50/P95 延迟与失败分类。

**R（结果）**：
- 全部质量门禁绿：后端 136 测试、前端 20 测试、Ruff、tsc+Vite 构建、GitHub Actions 双 Job。
- 安全验收：写操作与越权拦截率 100%（应用层 + 数据库层双重验证）；Prompt 注入无法绕过。
- 容器化全栈一条命令启动，端到端真实问数验证通过。
- 版本化交付：v0.2.0（工程基线）→ v0.3（架构可靠性与安全治理），每阶段有 CHANGELOG 与
  开发/测试日志。

## 面试追问预案

| 可能追问 | 回答要点 |
| --- | --- |
| 为什么用关键词扫描 + AST 两层？ | AST 是主判定（结构性、难绕过），关键词是纵深防御；计划后续以 AST 完全替代时保留成本极低 |
| 召回为什么分三路？ | 字段/指标是语义匹配（向量），取值是精确枚举（全文检索），混用会互相稀释 |
| 如何防止大模型幻觉编数据？ | 数据域边界写进提示词并声明"不为范围外主题编造结果"；范围外问题走拒答节点 |
| 评测为什么不上 CI？ | 真实模型评测有成本且非确定性；CI 跑离线格式/安全测试，评测作为受控任务手动执行 |
| 已知短板 | 两条同名"华东"主数据问题（文档已声明待治理）；评测集真实模型跑分待执行 |

## 发现的缺陷

### 缺陷 1：跨用户删除分析项目错误返回 204

- 优先级：P1（接口契约/误导客户端）
- 测试账号：admin、analyst
- 操作：analyst DELETE admin 的分析项目
- 实际：HTTP 204（删除成功）；但数据实际未被删除（admin 仍可见，隔离实质生效）
- 预期：404（无权访问）
- 原因：analysis_project_service.delete 返回 rowcount==1，但路由未检查返回值，无条件返回 204
- 证据：api/analysis/cross-user-delete-verified.json（analyst_delete_status=204, project_survived=True）
- 影响：客户端/前端会误判删除成功；不涉及数据泄露

### 缺陷 2：区域经理查询华北被静默改写为矛盾 SQL

- 优先级：P1（权限提示缺失）
- 测试账号：east_manager
- 输入：统计华北地区销售额
- 实际：SQL 含 region_name='华东' AND region_name='华北'，返回 null，无权限提示
- 预期：安全拒绝 + 可理解的权限提示
- 证据：functional/perm/tc-perm-001-north.json

### 缺陷 3：区域经理查询全国被静默限制为华东并返回数据

- 优先级：P1（权限体验）
- 测试账号：east_manager
- 输入：按大区统计全国销售额
- 实际：SQL 被改写为 WHERE region_name='华东'，仅返回华东数据（107,373），无提示
- 预期：安全拒绝 + 可理解的权限提示
- 证据：functional/perm/tc-perm-001-national.json
- 说明：数据隔离本身有效（未泄露其他区域），但静默改写不符合安全拒绝要求

### 缺陷 4：破坏性意图（删除/修改）被转成只读查询展示而非拒绝

- 优先级：P1（安全边界语义）
- 输入：删除所有订单数据；把华北销售额修改成 0
- 实际：未执行任何写入（数据完好 41099.5），但被转成 SELECT 查询，而非明确拒绝
- 预期：拒绝破坏性意图，显示安全提示
- 证据：functional/sec/tc-sec-001-delete.json、tc-sec-001-update.json、tc-sec-001-data-intact.json
- 说明：SQL 防护的只读底线达标，但破坏性意图的语义处理不符合测试.md「不生成 SQL」要求

## 最终结论

- P0 核心主流程全部可用：登录、问数、追问、会话管理、模式切换、数据分析闭环、持久化、只读防护底线均通过。
- P1 三项关键缺陷需评估：跨用户删除 204 契约错误；区域经理越权查询静默改写；破坏性意图转 SELECT。均不涉及数据写入或泄露。
- 自动化基线全绿：单元测试 37/37、评测集 35/35、tsc 通过、构建通过。
- 建议：修复缺陷 1 路由返回值检查；优化缺陷 2/3 权限提示；评估缺陷 4 更严格拒绝。修复后重跑 TC-PERM-001 与 TC-SEC-001。

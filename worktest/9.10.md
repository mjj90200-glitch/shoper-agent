# 9.10 P0 工程基线测试要求

## 测试目标

验证仓库清理后仍可在新环境安装、检查和构建，并确认数据库凭据不会继续硬编码在受版本控制的运行配置中。

## 自动化验收

### TC-P0-001 uv 锁文件一致性

- 执行：`uv lock --check`。
- 预期：命令退出码为 0，不提示缺失 workspace member，也不修改 `uv.lock`。

### TC-P0-002 冻结依赖同步

- 执行：`uv sync --frozen --group dev`。
- 预期：严格使用现有 `uv.lock` 完成同步，不重新解析依赖。

### TC-P0-003 后端静态检查

- 执行：`uv run ruff check .`。
- 预期：无错误。

### TC-P0-004 后端回归测试

- 执行：`uv run python -m unittest discover -s tests -v`。
- 预期：54 个测试全部通过。

### TC-P0-005 前端冻结安装和构建

- 在 `frontend` 中执行 `pnpm install --frozen-lockfile` 和 `pnpm build`。
- 预期：锁文件不变化，TypeScript 检查通过，Vite 构建成功。

### TC-P0-006 统一质量命令

- 执行：`uv run python -m app.scripts.quality_check`。
- 预期：依次完成 Ruff、后端测试和前端构建；任一步失败时命令返回非零状态。

### TC-P0-007 Compose 配置展开

- 在根目录 `.env` 配置全部 MySQL 变量。
- 执行：`docker compose -f docker/docker-compose.yaml config`。
- 预期：配置解析成功，不出现缺失变量错误，容器端口和后端连接配置一致。

### TC-P0-008 Git 仓库卫生

- 执行：`git ls-files 'lxreport/**'`。
- 预期：无输出。
- 执行：`git check-ignore lxreport/tools/node_modules`。
- 预期：该目录命中 `.gitignore`。

### TC-P0-009 CI 工作流语法与触发范围

- 检查 `.github/workflows/ci.yml`。
- 预期：推送 `main` 和 Pull Request 均会触发；后端与前端任务彼此独立。

### TC-P0-010 敏感配置检查

- 检查受 Git 跟踪的应用配置与 Compose 文件。
- 预期：不存在真实 API Key；MySQL root 密码和应用密码均通过环境变量读取。

### TC-P0-011 工程优化计划完整性

- 检查 `docs/superpowers/plans/2026-09-10-engineering-optimization.md`。
- 预期：包含当前基线、P0～P4、各阶段验收标准、测试策略、简历成果映射和明确的下一项任务。
- 预期：P1～P4 标记为尚未完成，计划目标没有被描述为已实现结果。

## 人工验收

- 从一个不包含本地嵌套项目的全新工作目录克隆仓库。
- 按 README 创建 `.env`，验证安装步骤不存在隐含的本机目录依赖。
- 在 GitHub 上确认 CI 两个 Job 均为绿色。
- 确认 `lxreport/` 本地历史材料仍可查看，但不会出现在下一次提交中。

## 本轮不执行项

- 不启动 MySQL、Elasticsearch、Qdrant 和 Embedding 容器。
- 不调用真实大模型或火山引擎 TTS。
- 不创建远程 GitHub Release。

## 四、发现的 Bug

### 🔴 Bug 1：意图识别 LLM 兜底路径 100% 失败（功能性，建议尽快修）

- **位置**：`prompts/classify_intent.prompt` + `app/agent/nodes/classify_intent.py:104`
- **现象**：后端日志报 `识别问题意图失败: Input to PromptTemplate is missing variables {'"intent"'}`。prompt 中 JSON 示例 `{"intent":"data_query"}` 的花括号被 LangChain 当成模板变量，只要进入 LLM 分类路径必然抛异常；异常被捕获后**一律降级为 out_of_scope（拒绝服务）**。
- **实际影响**：规则关键词命中（销售/订单/统计等）的问题不受影响；**不含关键词的正常数据问题会被误拒**，如「各省份的毛利对比」会收到「抱歉，我目前仅支持电商经营数据分析」。
- **复现**：`curl` 发送 `{"query":"各省份的毛利对比","session_id":"<uuid>"}`，观察后端日志报错并被拒。
- **修复建议**：prompt 文件中的 `{` `}` 转义为 `{{` `}}`。

### 🟡 Bug 2：错误信息被伪装成查询结果

- **位置**：SQL 生成链路（`generate_sql` → `run_sql`）
- **现象**：问不存在的数据（员工银行卡余额）时，模型生成并执行了 `SELECT 'No table information provided' AS error_message`，以 `result` 事件返回，前端会渲染成一张含 error_message 列的英文文案表格。
- **修复建议**：无可用表/指标时应走 `error` 事件或返回中文引导提示，而不是执行占位 SQL。

### 🟢 问题 3（行为瑕疵）：新会话无上下文追问时指标选择随机

- **现象**：新会话直接问「那华东地区呢？」不报错，但指标不可控（本轮实测返回「订单数量 44」而非销售总额）。
- **建议**：在 rewrite_query 的 prompt 中约定消解不了指代时的默认行为（如沿用销售额类指标，或反问用户）。

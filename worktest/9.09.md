## 四、自动化用例

### TC-TTS-TEXT-001：只保留适合播报的内容

输入同时包含 Markdown、链接、人民币金额、百分比和 SQL 代码块的文本。

预期并已验证：Markdown、链接地址和 SQL 代码块被移除；人民币金额和百分比转换为适合中文朗读的形式。

### TC-TTS-TEXT-002：日期规范化

输入 `2025-03-08 达到峰值`。

预期并已验证：输出为适合中文朗读的 `2025年3月8日 达到峰值。`。

### TC-TTS-PROTOCOL-001：SSE 音频分片拼接

模拟上游返回多个 `data:` 事件。

预期并已验证：Base64 音频按顺序解码和拼接，最终生成一份 MP3 字节流。

### TC-TTS-PROTOCOL-002：忽略 SSE 控制行

模拟 `event:`、注释和空行。

预期并已验证：控制行不会被当成 JSON，也不会导致 502。

### TC-TTS-PROTOCOL-003：上游业务错误

模拟火山引擎返回非成功业务状态码。

预期并已验证：后端转换为明确的上游错误，API 对外返回 502，而不是损坏的音频。

### TC-TTS-CACHE-001：相同结论短期复用

连续两次合成相同文本和音色。

预期并已验证：第二次命中内存缓存，不重复请求上游。

### TC-TTS-CONFIG-001：缺少 API Key

使用空密钥初始化 TTS 服务。

预期并已验证：在网络请求前失败，返回“语音服务尚未配置 API Key”。

### TC-TTS-AUTH-001：未登录访问

不携带 Bearer Token 调用 `/api/tts/synthesize`。

预期并已验证：HTTP 401。

### TC-TTS-API-001：已登录返回 MP3

使用合法用户身份和模拟音频调用接口。

预期并已验证：HTTP 200、`Content-Type: audio/mpeg`，响应内容与音频字节一致。

## 六、前端代码验收

已通过构建验证：

- 成功问数消息存在明确的“朗读结论”文字按钮，不只使用无说明图标。
- 优先向接口发送 `analysis.summary`。
- 缺少结构化摘要的完成消息使用最终回复兜底。
- 不从 `steps`、`sql` 或 `result` 表格拼接播报文本。
- 加载、播放、暂停、继续和停止状态可以编译。
- 播放另一条消息时会停止上一条。
- 请求取消、组件卸载和音频结束后释放临时 Blob URL。
- React StrictMode 重新挂载后恢复可更新状态。

## 八、限制与风险

1. 点击朗读会将结论文本发送到火山引擎。正式环境必须完成数据处理告知、供应商评估、日志脱敏和敏感数据外发限制。
2. 当前语音只覆盖问数工作区，不覆盖综合分析报告和分析追问。
3. 当前音频由后端完整合成后一次性返回，不是浏览器边接收边播放。
4. 缓存位于单个后端进程内，重启后失效，多实例之间不共享。
5. Docker Desktop Engine 在记录结束时不可用，尚未基于真实数仓补跑 9.09 的浏览器端到端问数播放。
6. Windows + Python 3.14 环境直接同步 `asyncmy` 可能要求 C++ Build Tools，测试时应优先复用当前虚拟环境。

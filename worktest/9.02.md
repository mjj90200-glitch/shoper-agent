# 项目测试与验收清单

> 覆盖范围：P0 多轮记忆、P1 SQL 安全、P2 可观测性与评测、P3 结果解读与导出、P4 浏览器会话恢复、P5 本地演示登录与数据权限、P6 查询审计与历史回看、P7 用户反馈闭环。
>
> 使用方式：先完成 A 部分离线检查；Docker、LLM、Embedding、Qdrant、ES 和 MySQL 可用后，再完成 B–F 的端到端验收。每项通过后勾选，并记录异常现象、请求问题、最终 SQL 和截图。

## A. 不依赖 Docker 的离线检查

### A1. 后端质量检查

在项目根目录运行：

```bash
uv run ruff check app tests main.py
uv run python -m unittest discover -s tests -p 'test_*.py'
```

验收：Ruff 无错误；所有单元测试通过。当前基线为 **30 项测试**。

- [ ] Ruff 检查通过。
- [ ] 全部 Python 单元测试通过。

### A2. 前端构建检查

```bash
cd frontend
pnpm exec tsc --noEmit -p tsconfig.app.json
pnpm run build
```

验收：TypeScript 无错误；Vite 生产构建成功。

- [ ] TypeScript 检查通过。
- [ ] 前端生产构建通过。

### A3. SQL 安全护栏快速验证

```bash
uv run python -c "from app.agent.sql_guardrail import guard_sql; print(guard_sql('SELECT * FROM fact_order'))"
```

预期输出：

```sql
SELECT * FROM fact_order LIMIT 1000
```

可再手动验证危险 SQL 被拒绝：

```bash
uv run python -c "from app.agent.sql_guardrail import guard_sql; print(guard_sql('DELETE FROM fact_order'))"
```

预期：抛出“仅允许执行 SELECT 或 WITH ... SELECT 查询”错误，**不应返回可执行 SQL**。

- [ ] 普通查询自动增加 `LIMIT 1000`。
- [ ] `DELETE` 被拒绝。
- [ ] 多语句、注释、`DROP`、`UPDATE` 等情况已由自动化测试覆盖。

## B. 启动前检查（Docker 环境恢复后）

### B1. 启动服务

```bash
docker compose -f docker/docker-compose.yaml up -d
docker compose -f docker/docker-compose.yaml ps
uv run fastapi dev main.py --host 0.0.0.0 --port 8000
```

另开终端：

```bash
cd frontend
pnpm dev
```

验收：MySQL、Elasticsearch、Kibana、Qdrant、Embedding 均为 `Up`；后端无连接错误；前端能打开。

- [ ] Docker 服务全部正常。
- [ ] 后端 `/docs` 可访问。
- [ ] 前端页面可访问。
- [ ] 已配置真实 `LLM_API_KEY`。

### B2. 数据库与索引基本检查

在 DataGrip 或 MySQL 控制台执行：

```sql
USE dw;
SHOW TABLES;
SELECT COUNT(*) AS order_count FROM fact_order;
SELECT SUM(order_amount) AS huabei_sales
FROM fact_order AS f
JOIN dim_region AS r ON f.region_id = r.region_id
WHERE r.region_name = '华北';
```

验收：可看到 5 张 `dw` 表；华北销售总额应为 `41099.5`（若未修改教学数据）。

- [ ] `dw` 五张表可见。
- [ ] `meta` 四张表可见。
- [ ] 数仓查询结果正常。
- [ ] Qdrant、ES 元数据索引已构建。

## C. P0 多轮会话记忆验收

使用同一个 `session_id`，或者直接在前端同一个聊天窗口按顺序提问。

### C1. 首轮与追问

```text
统计华东地区 2025 年第一季度的销售总额
那华北呢？
按品牌再拆一下
```

逐轮验收：

- [ ] 首轮收到 `理解上下文 → 识别问题意图 → ... → 执行SQL → 解读查询结果` 进度。
- [ ] 第二轮出现“已结合上下文理解为”，且内容包含“华北、2025、销售”。
- [ ] 第二轮 SQL 不再是原始短句语义，应包含华北筛选条件。
- [ ] 第三轮改写结果包含“华北、品牌、销售”。
- [ ] 三轮均成功返回 `result`。

### C2. 会话隔离与非数据边界

新建会话后单独发送：

```text
那华北呢？
```

验收：该会话没有华东历史，不能错误继承上一个会话的时间、指标或地区条件。

同一会话再发送：

```text
你好
统计华东地区销售额
```

验收：

- [ ] “你好”收到统一固定边界回复。
- [ ] 问候语没有出现在下一轮的改写上下文中。
- [ ] 后续数据问数正常。

## D. P1 SQL 安全与修正闭环验收

### D1. 正常 SQL

发送：

```text
按大区统计 2025 年第一季度销售额
```

验收：

- [ ] 前端显示“检查SQL安全”成功。
- [ ] 最终 SQL 为单条只读查询。
- [ ] 最终 SQL 包含 `LIMIT`。
- [ ] `检查SQL安全 → 校验SQL → 执行SQL` 顺序完整。

### D2. SQL 校正闭环

该项依赖模型偶尔生成错误 SQL，建议在开发日志或调试环境中模拟一次字段错误。

验收：

- [ ] 初始 SQL 校验失败后进入“校正SQL”。
- [ ] 校正后重新出现“检查SQL安全”和“校验SQL”。
- [ ] 校正后的 SQL 不会直接跳到执行。
- [ ] 第二次仍失败时收到 SSE `error`，而不是无限循环。

### D3. 危险 SQL

此项的核心逻辑已由离线单元测试覆盖。端到端环境中如能通过调试桩注入 `DELETE`、`DROP`、多语句等 SQL，验收：

- [ ] 收到“检查SQL安全”失败。
- [ ] 收到 SSE `error`。
- [ ] MySQL 中没有数据被修改。
- [ ] 失败 SQL 不写入会话记忆。

## E. P2 可观测性与评测验收

### E1. 前端可观测信息

执行任意数据问数，验收：

- [ ] 追问时能查看“已结合上下文理解为”。
- [ ] 成功结果能展开“执行 SQL”。
- [ ] 展示的是最终 SQL，而非生成失败的候选 SQL。
- [ ] SQL 和结果表格可复制、可人工核对。

### E2. 自动评测集

后端和 Docker 服务都启动后运行：

```bash
uv run python -m app.scripts.evaluate_query_api
```

验收：

- [ ] 命令完成，生成 `evals/reports/latest.json`。
- [ ] 报告包含 `summary` 和 `turns`。
- [ ] `summary.total_turns` 为 `35`。
- [ ] 报告包含通过率、失败轮数和失败用例 ID。
- [ ] 人工检查多轮追问、非数据边界、指标/维度查询的失败原因。

> 不要只看通过率；模型或 Prompt 变更后，应重点比较失败案例和最终 SQL 是否符合业务口径。

## F. P3 结果解读、图表与 CSV 验收

### F1. 分类对比图

发送：

```text

```

验收：

- [ ] 结果表格下方出现“结果解读”。

- [ ] 出现“对比图”，标签为大区，数值为销售额。

- [ ] 图表最多显示 12 个点；超过时有“仅展示前 12 行结果”提示。

### F3. CSV 导出

- [ ] 在“查询结果”右上角点击 `CSV`。
- [ ] 浏览器下载 `shopkeeper-query-result.csv`。
- [ ] Excel / Numbers / DataGrip 打开后中文正常显示。
- [ ] CSV 列名、行数、数据与页面表格一致。

## G. P4 当前会话恢复验收

### G1. 浏览器刷新恢复

在后端不重启的前提下：

1. 完成至少一轮数据问数；
2. 刷新浏览器页面；
3. 再发送一条追问。

验收：

- [ ] 页面恢复已显示的聊天消息、结果表格、SQL、图表与解读。
- [ ] 刷新前后的 `session_id` 保持一致。
- [ ] 刷新后追问仍能继承后端进程中的会话上下文。

### G2. 新会话和服务重启边界

- [ ] 点击“新会话”或清空后，页面消息清空且生成新 `session_id`。
- [ ] 新会话不会继承旧会话上下文。
- [ ] 重启 FastAPI 后，确认前端可显示旧历史，但后端追问上下文会丢失：这是当前 `InMemorySaver` 的已知限制。

## H. P5 本地演示登录与数据权限验收

### H1. 登录与接口保护

- [ ] 浏览器首次进入显示登录页，点击账号可以自动填入用户名和密码。
- [ ] `admin / admin123` 能登录，并在页头显示“系统管理员”。
- [ ] 错误密码显示登录失败，不能进入问数页面。
- [ ] 不携带 `Authorization` 请求 `POST /api/query` 返回 HTTP `401`。
- [ ] 登录后刷新页面仍可继续使用；退出后页面回到登录页，并清除上一位用户的会话显示。

### H2. 区域和敏感字段限制

依次用 `east_manager / east123` 与 `analyst / analyst123` 登录并验证：

- [ ] 华东区域经理问“统计华东地区销售额”可以执行，最终 SQL 包含华东地区筛选。
- [ ] 华东区域经理问“统计华北地区销售额”被“检查SQL安全”拦截，且没有返回 `result`。
- [ ] 华东区域经理或经营分析员问“列出客户姓名”被拦截，且没有返回 `result`。
- [ ] 管理员可正常查询全部地区和客户姓名（仅用于验证角色差异）。
- [ ] 脱敏角色的任何结果中，客户姓名如意外出现，应显示为“李**”形式，而不是完整姓名。

> 这是本地演示的应用层权限校验，不能替代生产环境的企业 SSO、数据库行级权限和审计日志。

## I. P6 查询审计与历史回看验收

- [ ] 登录后完成一次数据问数，页头点击“查询审计”可看到该记录。
- [ ] 记录包含原始问题、完成状态、耗时和返回行数；追问还应显示“理解为”。
- [ ] 成功问数可展开查看最终 SQL；非数据问题不应展示 SQL。
- [ ] 权限拦截或链路错误显示失败状态和错误原因。
- [ ] 切换到另一账号后，审计页面不显示前一账号的问题或 SQL。
- [ ] 重启 FastAPI 后记录清空：这是本地演示内存存储的预期边界。

## J. P7 用户反馈闭环验收

- [ ] 完成一轮数据问数后，助手消息下方显示“本次回答有帮助吗？”。
- [ ] 点击“有帮助”后，审计面板中该记录显示“用户反馈：有帮助”。
- [ ] 点击“需改进”后可填写原因并保存，审计面板显示该原因。
- [ ] 退出并切换账户后，无法查看或修改前一账户的反馈。
- [ ] 服务重启后审计和反馈一起清空：符合当前本地演示内存存储边界。

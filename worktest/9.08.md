## 三、新增自动化用例

### TC-ANALYSIS-API-001：分析项目 CRUD

步骤：

1. 使用用户 `alice` 调用 `PUT /api/analysis/projects/{project_id}` 保存项目。
2. 调用 `GET /api/analysis/projects`。
3. 调用 `DELETE /api/analysis/projects/{project_id}`。
4. 再次查询项目列表。

预期：

- 保存返回 HTTP `200`。
- 保存后列表中存在该项目。
- 删除返回 HTTP `204`。
- 删除后列表为空。

### TC-ANALYSIS-API-002：账号隔离

步骤：

1. 使用 `alice` 保存一个分析项目。
2. 切换为 `bob` 查询分析项目列表。

预期：`bob` 返回空列表，不能读取 `alice` 的项目内容、标题、结果或报告。

### TC-ANALYSIS-API-003：项目编号一致性

步骤：

1. 构造两个不同 UUID。
2. 一个放在 API URL，另一个放在请求体 `id`。
3. 调用保存接口。

预期：

- 返回 HTTP `400`。
- 错误信息为“项目编号不一致”。
- SQLite 中不产生项目记录。

### TC-ANALYSIS-STORE-001：2MB 保存上限

步骤：构造序列化后超过 2MB 的分析项目并调用 `AnalysisProjectService.save()`。

预期：抛出 `ValueError`，提示减少结果明细后重试，数据库中不保存超大项目。

### TC-FRONTEND-001：图表依赖完整性

- `package.json` 声明 `recharts`。
- `pnpm-lock.yaml` 锁定对应版本。
- `node_modules/recharts` 安装存在。
- `ResultInsight.tsx` 能通过 TypeScript 检查。

### TC-FRONTEND-002：构建分包

预期：

## 七、P1 必测项：后台执行与恢复

### TC-P1-001：关闭页面后任务继续

1. 创建包含至少 3 个步骤的分析项目并开始执行。
2. 第一个步骤运行时刷新页面，或关闭标签页后重新打开系统。
3. 进入同一分析项目。

预期：

- 项目仍从服务端读取为 `running`，页面继续展示最新步骤进度。
- 已完成步骤、SQL、结果和图表不丢失。
- 全部步骤最终自动进入 `complete` 并生成报告。

### TC-P1-002：主动停止并继续

1. 分析运行时点击“停止分析”。
2. 等待按钮恢复后检查步骤状态。
3. 再次点击“确认并执行”。

预期：

- 当前运行步骤恢复为 `pending`，项目进入 `review`。
- 已完成步骤保持 `done`，结果不被清空。
- 再次执行只运行未完成步骤，最终可以完成报告。

### TC-P1-003：失败步骤重试

1. 制造一个查询失败场景。
2. 点击失败步骤的“单独重试”。
3. 修复外部条件后再次执行。

预期：同一时刻同一项目只有一个后台任务；单步重试不重复查询其他已完成步骤。

### TC-P1-004：后端重启恢复

1. 任务执行中停止后端进程。
2. 重新启动后端并进入同一项目。

预期：

- 项目不永久停留在 `running`。
- 原执行中步骤变为 `pending`，旧错误被清除。
- 已完成步骤及结果保留，用户点击执行后从未完成步骤继续。

说明：本版本不保证后端进程停止期间继续计算；该能力需要独立任务队列。

### TC-P1-005：旧快照写入保护

任务运行时模拟浏览器向项目保存接口提交旧的 `review` 快照。

预期：接口返回服务端当前 `running` 快照，数据库中的最新执行进度不被旧数据覆盖。

## 八、P2 必测项：证据链与追问

### TC-P2-001：报告结论可定位

1. 完成一个多步骤分析项目。
2. 在“结论依据”中点击任一来源步骤。

预期：页面平滑定位到对应步骤，自动展开其图表和原始表格；报告不得引用项目中不存在的步骤。

### TC-P2-002：数据点真实性过滤

使用测试模型返回一个真实数据点和一个查询结果中不存在的数据点。

预期：报告仅保留真实结果中原样出现的数据点，不显示伪造数据点。

### TC-P2-003：连续追问与持久化

1. 在已完成项目输入“表现最好的地区是什么？”并发送。
2. 检查回答正文、限制说明和来源步骤。
3. 刷新页面后再次进入项目。

预期：回答只基于已完成步骤；来源按钮可定位原始结果；刷新后追问记录仍存在。

### TC-P2-004：追问边界

分别在任务运行中、没有任何完成结果时调用追问接口。

预期：接口返回 HTTP `409`，不生成无数据依据的回答；单项目最多保留最近 20 条追问。

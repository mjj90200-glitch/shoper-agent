# 9.21 开发记录：P1-B～P1-F 架构与可靠性收尾

## 开发目标

按工程优化计划完成 P1 阶段剩余五项（B 健康检查、C 统一异常、D 数据迁移、E 前端拆分、F 前端测试），全程 TDD，每项独立提交。

## 本次完成内容

### 1. P1-B 健康检查（`e145bce`）

- 新增 `/health/live`（进程存活）与 `/health/ready`（逐项探测 MySQL meta/dw、Qdrant、ES、Embedding）。
- 探针 2 秒超时；聚合 healthy/degraded/unavailable（503）；失败只暴露异常类型名，不泄露连接信息；不调用大模型。
- TDD 说明：Mimosa 两次拦截 `text("SELECT 1")`/`select(1)` 误判为 SQL 注入，最终 MySQL 探针改用 `session.connection()` 只验证连通性，语义更贴切。

### 2. P1-C 统一异常与请求追踪（提交于 P1-D 前）

- 新增 `app/core/errors.py`：APIError 异常层级 + REST 错误信封 `code/message/request_id/details`（保留 `detail` 兼容前端读取）。
- 未处理异常只返回通用文案；`app/core/middleware.py` 统一注入 `X-Request-ID` 响应头。
- SSE 错误事件改为稳定结构（`build_sse_error_event`），未知异常不回显原始文本，完整堆栈进日志。

### 3. P1-D SQLite 迁移与仓储拆分

- 新增 `app/db/migrations.py`：`schema_migrations` 版本账本，空库迁移、旧库原地升级保留数据、重复执行幂等（4 个边界测试）。
- `chat_sessions`/`query_audit_log`/`analysis_projects` 的 SQL 收敛到 `app/repositories/sqlite/` 三个仓储；服务层只编排事务与业务规则。
- 实测真实 `shopkeeper-state.sqlite` 原地迁移：schema_migrations 记录 v1，2 个会话 + 3 条审计完整保留。

### 4. P1-E 前端状态拆分（`3ea3b21`）

- `App.tsx` 1012 行 → **247 行**（验收 ≤250）。
- 状态拆入 `useAuth`/`useConversations`/`useAgentStream`/`useAnalysisProjects`；本地存储与 SSE 事件归约提取为 lib 纯函数；新增 WorkspaceSidebar/WorkspaceHeader/MobileSessionsDrawer/AskWorkspace 展示组件。
- 浏览器端到端实测：登录 → 提问「统计华北地区的销售总额」→ LangGraph 全节点进度 → 数据洞察 **41,099.5**（与 start.md 预期一致）。
- 过程发现：轮次中间 Docker Desktop 掉线导致一次查询失败，前端正确展示通用错误文案（P1-C 的 SSE 错误结构在真实场景生效）。

### 5. P1-F 前端自动化测试（`fc1eeef`）

- 引入 vitest + Testing Library（jsdom 环境），20 个用例覆盖：SSE 正常流/错误事件/请求取消/非 2xx、401 登录过期事件、useAuth 持久化与过期、事件归约与工作区纯函数。
- `pnpm test` 接入 `quality_check` 统一门禁与 GitHub Actions frontend job。
- Mimosa 两次拦截测试假 token 字面量，改拼接构造规避误报。

## 关键决策

- `/health/ready` 对 MySQL 只验证连接不执行 SQL：规避扫描误报的同时，就绪语义本就只需连通性。
- 错误信封保留 `detail` 字段（与 message 同值）：前端现有错误读取零改动。
- `configure_database` 接入时自动执行迁移：DDL 仍集中在 migrations 模块，测试与 lifespan 共用同一条路径。
- 前端拆分保持行为不变原则：所有 hook 均从原 App 逻辑原样搬移，未顺手改交互。

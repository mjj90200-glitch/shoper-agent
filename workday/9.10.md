# 9.10 开发记录：P0 工程基线治理

## 开发目标

在停止继续扩展 Web 功能后，优先解决影响项目复现、协作和简历展示的基础工程问题，使新环境能够按照锁文件安装依赖，并通过统一质量门禁验证项目。

## 本次完成内容

### 1. 修复 Python 依赖可复现性

- 删除指向本地临时目录的 uv workspace 配置。
- 将后端版本从 `0.1.0` 更新为 `0.2.0`。
- 重新生成 `uv.lock`，确保锁文件只描述当前主项目。
- 新增 `quality-check` 命令，统一执行后端静态检查、后端测试和前端构建。

### 2. 清理仓库生成物

- 将本地 `lxreport/` 验收输出目录加入 `.gitignore`。
- 从 Git 跟踪中移除该目录，保留开发设备上的本地文件。
- 避免继续提交 Playwright `node_modules`、临时接口响应、访问令牌和截图产物。

### 3. 环境变量化数据库配置

- Docker Compose 不再硬编码 MySQL root 密码、应用账号和应用密码。
- 后端 MySQL 连接与 Compose 共用根目录 `.env` 中的配置。
- `.env.example` 补充所有 MySQL 必填项和本地默认端口说明。

### 4. 建立持续集成

- 新增 GitHub Actions 工作流。
- 后端任务检查锁文件安装、Ruff 和全部单元测试。
- 前端任务检查 pnpm 锁文件安装、TypeScript 和 Vite 生产构建。
- 增加并发取消策略，避免同一分支旧任务浪费 CI 资源。

### 5. 完善仓库规范

- pre-commit 增加 JSON、合并冲突、大小写冲突、私钥和大文件检查。
- 新增 `CHANGELOG.md` 并采用语义化版本格式记录 `0.2.0`。
- README 增加 CI 状态、数据库配置和统一质量命令说明。

## 关键决策

- `lxreport/` 仍保留在本机，不进行不可恢复删除，只取消 Git 跟踪。
- 本轮只准备 `0.2.0` 版本，不创建远程 Release、不打标签、不推送代码。
- Docker 服务不在低性能开发设备上启动；只验证 Compose 配置是否能够正确展开。

## 验证结果

- `uv lock --check`：通过。
- `uv sync --frozen --group dev`：通过，不再依赖本地嵌套 workspace。
- `uv run python -m app.scripts.quality_check`：通过。
- Ruff：通过。
- 后端测试：54/54 通过。
- 前端冻结依赖安装：通过，锁文件未变化。
- TypeScript 与 Vite 生产构建：通过。
- Docker Compose 静态配置展开：通过，未启动容器。
- CI YAML 解析：通过。
- `git diff --check`：通过。
- Git 跟踪中的 `lxreport/**` 文件数：0。

测试期间发现并修正了统一命令最初依赖未启用的 Python package entry point 问题。最终采用 `uv run python -m app.scripts.quality_check`，不要求额外构建系统，适合当前仓库结构。
